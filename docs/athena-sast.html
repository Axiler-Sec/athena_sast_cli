Athena SAST

Product documentation for the Athena SAST CLI, local OWASP CI/CD gate, engine client, and CI wrappers (GitHub Actions, Jenkins, Azure DevOps). Version 1.0.0 · Apache-2.0.

This page is the operator manual in one place. Step-by-step CI checkpoints (G0–G4, J0–J4, A0–A4) also live in docs/CI.md.

Open this file in a browser. To get Word: File → Save As → Word Document, or print to PDF.

Overview

Athena SAST finds security issues in source, IaC, dependencies, containers, secrets, and CI/CD pipeline YAML. The CLI is the backbone of plugins (same model as commercial SAST CLIs): Jenkins, GitHub Actions, and Azure DevOps install the athena binary and execute it. They contain zero scan logic.

Two scan depths:

  • Local OWASP CI/CD gate — regex rules ATH001–ATH054 on disk. No API key. Tagged source: local_owasp. Covers the OWASP CI/CD Security Cheat Sheet (CICD-SEC-1 through CICD-SEC-10).
  • Engine client — HTTP POST to Athena FastAPI engine routes (OpenGrep, Trivy, KICS, Syft, and related product agents). Requires ATHENA_API_URL and ATHENA_API_KEY. Tagged source: engine.

The web UI is a sibling consumer of the same FastAPI engine. It does not call this CLI.

System architecture

You (laptop or CI)
   →  Athena CLI  (athena / python3 athena.py)
         →  local OWASP gate (files on disk)
         →  FastAPI engine  (ATHENA_API_URL)
                →  OpenGrep, Trivy, KICS, Syft, …

GitHub / Jenkins / Azure  →  install CLI  →  exec athena scan
Web UI                    →  engine HTTP  (does not exec the CLI)
Localhost trap. Cloud CI (GitHub-hosted ubuntu-latest, Microsoft-hosted Azure agents) cannot call http://127.0.0.1:8012 on your laptop. First pipelines must be local-gate only. Engine-from-CI needs a URL the agent can reach (deployed engine, or a self-hosted runner on the same network as the API).

Honesty and claims

  • Product agents do not return SARIF. The CLI builds SARIF 2.1.0 and labels it sarif_source: cli_normalized. Never send include_sarif: true to agents.
  • athena compliance prints mapped controls (heuristic). It is not a SOC 2 / PCI certification.
  • Local “compliant” copy means the regex gate found nothing — not a legal attestation.
  • CVE / CWE / CVSS appear on engine findings when the engine sends them, and are omitted when it does not.

Install the CLI

Requirements: Python 3.10+.

cd athena-sast-cli
python3 athena.py version
# Athena SAST v1.0.0

python3 -m pip install .     # provides the `athena` console script
athena version

python3 -m unittest discover -s tests

Package name: athena-sast 1.0.0. Entry point: athena = pkg.cli:main.

CLI Docker image (no secrets in the image):

docker build -t athena-sast-cli .
docker run --rm -v "$PWD":/src -w /src athena-sast-cli scan --target . --modes pipeline --fail-on high
# Engine: docker run --rm -e ATHENA_API_URL -e ATHENA_API_KEY -v "$PWD":/src -w /src athena-sast-cli scan --repo URL --branch main

Cursor MCP: copy .cursor/mcp.json.example to a local mcp.json, set cwd and env. Run athena mcp is stdio-only — not a public port.

Configuration and authentication

Precedence

CLI flag > environment variable > athena.yaml > built-in default. The engine and UI do not read athena.yaml.

Environment (auth is env-only)

VariablePurpose
ATHENA_API_URLEngine base URL, no trailing slash. Example: http://127.0.0.1:8012 (Docker maps host 8012 → container 8000).
ATHENA_API_KEYScanner-role engine key, sent as X-API-Key. Prefer ath_live_… (not the lab master API_KEY). Never a CLI flag. One key per repo/org — no shared master keys in CI (AXI-856).
ATHENA_REPO_TOKENGit token for private clones. Public repos often omit this.
ATHENA_REGISTRY_USER / ATHENA_REGISTRY_PASSWORDPrivate container registries.
ATHENA_HTTP_TIMEOUTSeconds. Default 600.
There is no --api-key. Flags would land in shell history (CICD-SEC-6). Composite GitHub Actions cannot read secrets.*; the caller workflow must set env:. Plugin scripts must start with set +x — never set -x (tokens in plaintext logs). The CLI redacts ath_live_ / ghp_ / env secret values from errors and saved raw files.

Default athena.yaml

fail_on: high
format: sarif
output: athena-results.sarif
modes:
  - code-review
  - secrets
  - iac
  - sca
  - pipeline
exclude:
  - "tests/**"
  - "**/*.test.py"
  - "vendor/**"

If you pass --format without --output, results print to stdout (so tests and interactive use are not swallowed by yaml output:). Prep commands (repo verify, repo branches) write a file only when you pass --output on the CLI.

Quick start

Local gate (no engine)

python3 athena.py owasp
python3 athena.py scan tests/targets/bad_pipeline.yml --format table
echo $?    # 1 = findings at/above fail-on

python3 athena.py scan tests/targets/clean_app.py --fail-on low --format table
echo $?    # 0 = clean

Engine (laptop)

export ATHENA_API_URL="http://127.0.0.1:8012"
export ATHENA_API_KEY="(same as FastAPI API_KEY)"

python3 athena.py repo verify \
  --repo https://github.com/octocat/Hello-World.git --branch master

python3 athena.py scan \
  --repo https://github.com/ORG/APP.git --branch main \
  --target . \
  --modes code-review,secrets,iac,sca,pipeline \
  --format sarif --output athena-results.sarif \
  --json-output athena-results.json \
  --fail-on high --quiet

Orchestrator order: repo verify → engine agents sequentially → local pipeline gate on --target → merge → write files → exit 0 or 1. Post-scan commands (pr create, sbom, compliance) are never auto-run from athena scan.

Shared flags on scan-style commands: --format table|json|sarif|junit, --output, --json-output, --fail-on critical|high|medium|low, --exclude, --quiet, --raw-dir (default athena-results/raw/; raw engine JSON is saved before parse).

401/403 → “auth failed”, exit 2. 5xx → retry once, then exit 2. Engine POSTs are synchronous today (200 + JSON). The client is poll-ready only if a future 202 body includes status_url; the CLI does not invent GET /status.

Running scans

athena scan without --repo walks --target (or the positional path) with local rules. With --repo it verifies the repository, then runs each mode in --modes. Mode pipeline is always local. Mode container needs --image registry/repository:tag.

Default CI command (what plugins exec when engine env is set):

athena scan --repo URL --branch BRANCH --target . \
  --modes code-review,secrets,iac,sca,pipeline \
  --format sarif --output athena-results.sarif \
  --json-output athena-results.json --fail-on high --quiet

First wrapper jobs omit --repo and use --modes pipeline so they work without an API key.

Exit codes and policy gate

Frozen public contract. Never add a fourth code.

CodeMeaningCI
0Scan finished. Nothing at or above --fail-on.Green
1Scan finished. Findings at or above --fail-on.Failed policy (tool worked)
2Could not run (bad path, missing env, auth, engine down).Broken tool — not “no vulns”

Default --fail-on high: Critical and High fail the build; Medium and Low do not.

Results, SARIF, and JSON

  • table — human findings list.
  • json — Athena schema schema_version: 1.0, tool athena, summary.by_source, summary.by_owasp_risk.
  • sarif — SARIF 2.1.0, runs[].properties.sarif_source = cli_normalized.
  • junit — for Jenkins Test Result.

Always write SARIF to a file in CI (--output). GitHub Code Scanning, Azure artifacts, and GitLab ingest files, not stdout.

CI checks capability

Engineering spec (ENG-74 split, AXI-856 token controls, v1 vs later): docs/CI-CHECKS.md.

ENG-74 is the plugin wrappers (install + exec this CLI). This CLI owns the checks, outputs, and credential hygiene. Plugins are a child of the CLI, not a second scanner.

Which checks, what triggers them, what comes out

  • Checks. Local regex gate (modes: pipeline, source: local_owasp, CICD-SEC-1…10) and, when engine env is set, product agents (source: engine).
  • Triggers. push / pull_request (GitHub), Jenkins SCM builds, Azure trigger/pr, or a laptop athena scan. Never pull_request_target plus checkout of the PR head (pwn request — secrets exposed to fork PRs).
  • Output. Exit 0/1/2, CLI-normalized SARIF, Athena JSON, JUnit on Jenkins.
v1 non-negotiable (AXI-856): scanner-role keys only; no argv secrets; CLI log redaction; set +x in wrappers; pin our Action dependencies to a commit SHA; warn against pwn request. OIDC short-lived tokens, canary keys, GitHub secret-scanning partner, and ENG-58-style anomaly detection are later (control plane / engine).

The local gate reads files. It does not run the target’s postinstall or build scripts (CICD-SEC-4 on the CLI side). Engine isolation of cloned third-party trees is an engine design constraint — do not retrofit it after the scan host is set.

Distribute this Action as uses: ORG/athena-sast-cli@COMMIT_SHA. A compromised plugin is a supply-chain hit on every customer (CICD-SEC-3). Artifact signing and self-hosted runner hardening are later; keep a line in the spec.

CI plugins (wrappers)

A wrapper only: (1) installs the CLI, (2) execs athena scan (the gate), (3) optionally athena monitor (record; does not fail on findings), (4) always publishes SARIF/JSON (and JUnit on Jenkins). The gate is the CLI scan exit code. Do not put regex or API calls in YAML.

Shared process: prove the command on a laptop → first pipeline = local gate (no secrets, no --repo) → then platform secrets and full modes when the agent can reach the engine. Checkpoints are in docs/CI.md.

GitHub Actions

Composite action: repo-root action.yml. Caller (local gate): .github/workflows/athena.yml with uses: ./, modes: pipeline, no secrets. Pin third-party actions to a commit SHA (actions/checkout@11bd7190… = v4.2.2). Code Scanning upload uses github/codeql-action/upload-sarif@b8ed34e6ff8a3049f4f8c90c055bf2397a014474.

Engine job: caller sets env.ATHENA_API_URL / ATHENA_API_KEY from secrets, and passes repo / branch. If this CLI is a separate repo, pin uses: ORG/athena-sast-cli@COMMIT_SHA — never @main.

Jenkins

Root Jenkinsfile (copy in plugins/Jenkinsfile). First job does not call credentials() (missing IDs fail before scan). Agent needs Python 3, pip, and this folder as workspace (pip install .). Artifacts always archived. JUnit from a second local scan; the SARIF scan exit still gates the build.

Engine (J4): bind secret text IDs athena-api-url, athena-api-key, athena-repo-token onto env vars, set REPO_URL. Both ATHENA_API_URL and REPO_URL switch modes to the full engine set.

Azure DevOps

Root azure-pipelines.yml (copy in plugins/azure-pipelines.yml). Microsoft-hosted ubuntu-latest. Do not set continueOnError on the scan step. Artifacts publish with condition: always(). --repo is added only when ATHENA_API_URL starts with http (unexpanded $(ATHENA_API_URL) is ignored).

Workspace root must be this CLI. If Azure builds the parent athena_sast folder, change install to python3 -m pip install ./athena-sast-cli.

A4: Library variables ATHENA_API_URL (no padlock), ATHENA_API_KEY (padlock), optional token. URL must be reachable from the hosted VM — not localhost.
